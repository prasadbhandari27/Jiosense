# /oneui:setup-android

Create a brand-new **native Android** (Jetpack Compose) app pre-wired with JDS.

## Flow
1. **Ask the user for four values — never guess them:**
   - `appName` — display name, e.g. "Jio Store" (also the app folder + `Theme.<Name>` style).
   - `packageName` — reverse-domain id, e.g. `com.jio.jiostore` (applicationId + namespace + Kotlin package).
   - `brandName` — one of `jio`, `reliance`, `tira`, `one_ui_theme`, `swadesh`, `native_test`.
   - `themeName` — the JDS theme for that brand, e.g. `JioMart` or `Default`.
2. Call `create_oneui_android_app` (server `oneui`) with those four (plus optional `cwd`, `force`).
   It clones a baked snapshot of `JdsExternalApp` with its versions untouched (JDS 4.0.0-alpha-03,
   Compose BOM 2025.04.01, AGP 8.12.2, Kotlin 2.1.20, Gradle 8.14.3), rewrites the app identity,
   points `app/jds-themes.json` and `MainActivity`'s `FoundationTheme` at the brand/theme, and
   returns a runbook. If any of the four is missing the tool returns a checklist to put to the user.
3. Follow the returned runbook: set the JDS feed credentials (JFrog + Azure) in
   `~/.gradle/gradle.properties`, then run `./gradlew generateDesignTokens`, then build
   (`./gradlew :app:installDebug`, or open the folder in Android Studio).

## Notes
- The MCP writes every file itself but does **NOT** run Gradle (that needs JDK 21 + the Android
  SDK + private-feed credentials) — the generate/build steps are emitted for the user to run.
- `registerAppThemes()` is auto-generated by `generateDesignTokens` and is already called in
  `MainActivity` before `FoundationTheme` — nothing to wire by hand.
- The cloned `settings.gradle.kts` ships with **no secrets**; the user supplies their own feed creds.
